# InvisTags 1.2.0

The first stable release of the two visibility toggles from the 1.1 beta. Both
are **off by default** and can be changed at runtime from the config screen or
with `/invis`.

## Gear reveal

Some servers strip equipment packets so invisible players look completely
empty. InvisTags remembers the gear your client actually saw and redraws it
while the player is invisible — armour, main hand and off hand.

Toggle: **Reveal invisible players' armour and held items**, or `/invis gear true`.

## Vanished-player flag

A player who is present in the world but missing from the tab list gets a red
`[VANISHED]` suffix on their nametag and a one-time chat alert. Detection is
skipped while the tab list is empty, so servers that hide the whole list do not
produce false positives.

Toggle: **Flag vanished players (no tab entry)**, or `/invis vanished true`.

## Config and command

![InvisTags config screen](https://raw.githubusercontent.com/MohenjoMC/Invistags/main/docs/screenshots/1.2.0/config-screen.png)

![In-game /invis status](https://raw.githubusercontent.com/MohenjoMC/Invistags/main/docs/screenshots/1.2.0/status-command.png)

`/invis` prints the current state; each option also takes `true`/`false`:

```
/invis skin|nametag|mobs|gear|vanished [true|false]
/invis vanished list
/invis remember [true|false]
/invis config
```

## Tested

- 16 unit tests per version branch (config persistence, vanish-detection edge cases)
- Client gametest on 1.21.11, 26.1.2, 26.2 and 26.3: real world, config screen, `/invis`
- Two-player test: a modded client observes the Manchulla bot while the server
  strips its gear and applies invisibility, with the toggle compared on and off

## Notes and limits

- Gear can only be restored once your client has seen it. Gear worn only while
  invisible cannot be reconstructed.
- Client-side only — no server plugin needed.
- The vanished flag depends on the tab list; a server that hides it entirely
  disables detection by design.
